Deep Dive — QuadTree & Geospatial Index

lesson
⏱ 15 min
📖 Chapter 28, Lesson 2

🎯 Learning Objectives

  • Compare fixed grid, geohash, and QuadTree spatial indexing structures
  • Design QuadTree subdivision using a tunable max-places-per-leaf threshold
  • Implement range search that correctly handles queries near cell boundaries
  • Separate spatial candidate retrieval from exact-distance and category post-filtering

Deep Dive — QuadTree & Geospatial Index

Lesson 1 established that scanning 200M places per query is infeasible, and that the ~5GB spatial index fits comfortably in memory. This lesson designs that index — the structure that turns "give me everything within 2km of (lat, lng)" into a fast, bounded lookup instead of a linear scan.

1. Spatial Indexing Options

StructureHow it worksTradeoff
Fixed gridDivide the map into equal-size cells (e.g., 1km²); each cell lists the places inside itSimple, but wastes cells over oceans/deserts and undersizes cells in dense cities — one-size-fits-all granularity doesn't match real place density
GeohashEncode lat/lng into a base32 string where shared prefixes mean spatial proximity; index by string prefixSimple to shard (prefix ranges) and store in any KV store, but has awkward edge cases at grid-cell boundaries and the poles
QuadTreeRecursively subdivide a region into four quadrants only where place density is highAdapts cell size to density (small cells in Manhattan, large cells in rural areas) — the best fit for highly uneven place distribution, at the cost of a more complex structure to build/traverse

We use a QuadTree: place density varies by orders of magnitude between a dense downtown and a rural highway, and a QuadTree is the only one of the three that adapts its resolution to that variance automatically.

2. QuadTree Structure & Subdivision

QuadTreeNode:
  boundary: (minLat, minLng, maxLat, maxLng)
  places:   list of place_ids in this node       // only populated on leaf nodes
  children: [NW, NE, SW, SE]  or  null (leaf)

MAX_PLACES_PER_LEAF = 500   // subdivide once a leaf exceeds this

insert(node, place):
  if node is leaf and len(node.places) < MAX_PLACES_PER_LEAF:
      node.places.append(place)
      return
  if node is leaf:                      // over threshold — subdivide
      node.children = split into 4 quadrants
      redistribute node.places among the 4 children
      node.places = null
  insert(child containing place.location, place)

The ~500-places-per-leaf threshold is a tunable knob: a smaller threshold means finer resolution (more, smaller leaves) at the cost of a deeper tree; a larger threshold means fewer index lookups but coarser candidate sets that need more post-filtering.

💡 Interview signal: Naming a concrete subdivision threshold (e.g., 500) rather than leaving it abstract shows you understand this is a tunable, measurable parameter — expect a follow-up like "what if 500 is too coarse for Manhattan?"

3. Range Search & Neighbor-Cell Traversal

search(node, queryCenter, radius):
  if node.boundary does not intersect the search circle: return []
  if node is leaf:
      return [p in node.places if distance(p, queryCenter) <= radius]
  results = []
  for child in node.children:
      results += search(child, queryCenter, radius)     // recurse into overlapping quadrants only
  return results

The tricky case: a search radius near a leaf's boundary can include places that live in a neighboring leaf, not just the leaf containing the query point. The traversal above handles this naturally by recursing into every child whose boundary intersects the search circle — not just the one containing the center point — so results correctly span leaf boundaries.

💡 Interview signal: Interviewers frequently probe "what if the user is standing right at the edge of a cell?" — answering with "intersect the search circle against node boundaries, not just point-in-node containment" is the expected fix.

4. Post-Filtering

  • The QuadTree returns candidates whose bounding cell intersects the search radius — a final exact-distance check and category filter are applied after retrieval
  • Category/keyword filters are applied post-retrieval rather than baked into the tree structure — the tree only needs to be one thing (a spatial index) done well

Key Takeaways

  • A QuadTree adapts cell granularity to place density, unlike a fixed grid or geohash — critical given how unevenly places are distributed
  • Subdivision is governed by a tunable max-places-per-leaf threshold, trading tree depth against candidate-set size
  • Range search must recurse into any child whose boundary intersects the search circle, not just the leaf containing the query point, to avoid missing edge-of-cell results
  • The tree returns candidates by bounding-box overlap; exact distance and category filtering happen as a post-retrieval pass

Interview Tips

  • Justify QuadTree over grid/geohash by pointing at uneven place density — don't just assert it's the standard answer
  • State the leaf-size threshold as a concrete, tunable number, and be ready to discuss the depth-vs-candidate-set tradeoff
  • Preempt the boundary-edge-case question by explaining bounding-box intersection in the traversal, before the interviewer asks
  • Keep the tree single-purpose (location only) — resist folding category filters into the tree structure itself
